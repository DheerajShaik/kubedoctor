## Kubernetes evidence and collection

| Source | Design implication |
| --- | --- |
| [kubectl plugins](https://kubernetes.io/docs/tasks/extend-kubectl/kubectl-plugins/) and [kubeconfig contexts](https://kubernetes.io/docs/concepts/configuration/organize-cluster-access-kubeconfig/) | Install `kubectl-doctor` on PATH and handle its arguments and kubeconfig context in the plugin process. Resolve explicit options locally and exercise discovery and invocation with a real kubectl. |
| [Kubernetes API concepts](https://kubernetes.io/docs/reference/using-api/api-concepts/), [client-go](https://github.com/kubernetes/client-go), and [Kubernetes releases](https://kubernetes.io/releases/) | Use stable APIs with bounded `limit` and `continue` paging, distinct response and visibility outcomes, explicit deadlines, and a shared rate limiter. One collection spans independent resource lists and describes an observation interval. Kubernetes lists 1.35–1.37 as maintained minors. Validate the actual minors before claiming them. |
| [Secrets](https://kubernetes.io/docs/concepts/configuration/secret/), [RBAC good practices](https://kubernetes.io/docs/concepts/security/rbac-good-practices/), and [ConfigMaps](https://kubernetes.io/docs/concepts/configuration/configmap/) | A required missing reference may prevent startup. Optional references and an absent literal environment variable have separate semantics. Use a corroborated event and an actual configured reference to report Secret evidence without body reads. Restrict ConfigMap inspection to specifically referenced objects and retain only presence and key membership. |
| [Pod lifecycle](https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/) and [node status](https://kubernetes.io/docs/reference/node/node-status/) | Distinguish current waiting, current termination, and historical termination. Use explicit OOMKilled reason and timing, a current scheduling condition and UID-matched warning, and the recorded status and transition time for node readiness and pressure. |
| [Deployments](https://kubernetes.io/docs/concepts/workloads/controllers/deployment/) and [DaemonSets](https://kubernetes.io/docs/concepts/workloads/controllers/daemonset/) | Use observed generation, desired and available counts, and an appropriate rollout signal. Account for paused Deployments, zero desired replicas, and progress while a rollout is active. |
| [StorageClasses](https://kubernetes.io/docs/concepts/storage/storage-classes/#volume-binding-mode) | `WaitForFirstConsumer` coordinates provisioning and topology with scheduling. Distinguish expected waits, an actual failed binding or provision operation, and missing class or event visibility. |
| [EndpointSlices](https://kubernetes.io/docs/concepts/services-networking/endpoint-slices/) and [Services](https://kubernetes.io/docs/concepts/services-networking/service/) | Aggregate all slices associated with a Service, using owner UID where present. A terminating endpoint can still be serving during a rollout. With `publishNotReadyAddresses`, the `ready` bit reflects publication behavior. Account for services with manually managed slices, external DNS and headless addressing. Prefer EndpointSlices and reserve legacy Endpoints for an unsupported API. |
| [Ingress](https://kubernetes.io/docs/concepts/services-networking/ingress/) and [DNS debugging](https://kubernetes.io/docs/tasks/administer-cluster/dns-debugging-resolution/) | Confirm Service backend names and service-port references with sufficient visibility. DNS component and Service observations describe infrastructure state. Workload-level resolution requires separate active evidence. |
| [NetworkPolicies](https://kubernetes.io/docs/concepts/services-networking/network-policies/) | Evaluate ingress and egress separately and combine selected policies additively. A static isolation advisory depends on the policy objects and selectors inspected. Enforcement and packet delivery depend on the network implementation and runtime conditions. |
| [PodDisruptionBudgets](https://kubernetes.io/docs/tasks/run-application/configure-pdb/) | Zero allowed voluntary disruptions can be intentional and affects maintenance or eviction. Check the observed generation and distinguish this constraint from application availability. |
| [Resource usage monitoring](https://kubernetes.io/docs/tasks/debug/debug-cluster/resource-usage-monitoring/) and [resource metrics pipeline](https://kubernetes.io/docs/tasks/debug/debug-cluster/resource-metrics-pipeline/) | Requests and limits are configuration. Metrics API CPU covers a reported measurement window, and memory represents working set at the sample timestamp. Label both with their units and timing. Historical sizing needs a separate historical source. |
| [Object names and IDs](https://kubernetes.io/docs/concepts/overview/working-with-objects/names/) and [Event API](https://kubernetes.io/docs/reference/kubernetes-api/events/event-v1/) | Use UID to avoid attributing events to a replacement object with the same name. Treat warnings as supplemental, time-bounded evidence and avoid emitting free-text event notes or messages. |

## Tooling and interoperability

- The public Go module proxy reported client-go v0.37.2 and Cobra v1.10.2. client-go v0.37.2 and v0.36.5 both declare minimum Go 1.26.0. The Go downloads service listed Go 1.27.4 as a current stable toolchain. The Go project's vulnerability tooling reports reachable known vulnerabilities in application code, dependencies, and the standard library. Pin the build toolchain and scanner and record the scan result on the tested revision. [client-go v0.37.2 manifest](https://raw.githubusercontent.com/kubernetes/client-go/v0.37.2/go.mod) [Cobra v1.10.2](https://github.com/spf13/cobra/releases/tag/v1.10.2) [Go downloads](https://go.dev/dl/) [Go vulnerability management](https://go.dev/security/vuln/)
- kind v0.33.0 supplies published digest-pinned node images for Kubernetes 1.35.8, 1.36.4 and 1.37.0. A disposable named cluster with its own kubeconfig exercises real controller behavior and plugin invocation. Installed artifact checks in a fresh PATH also work against the controlled HTTP transport fixture. [kind v0.33.0](https://github.com/kubernetes-sigs/kind/releases/tag/v0.33.0) [kind quick start](https://kind.sigs.k8s.io/docs/user/quick-start/)
- The official MCP Go SDK v1.8.0 declares Go 1.25.0 and protocol compatibility from 2024-11-05 through 2026-07-28. Both 2025-11-25 and 2026-07-28 document stdio with newline-delimited JSON-RPC. The 2026-07-28 revision carries protocol metadata per request, and its stdio binding specifies how clients and servers detect the legacy initialization flow. Use the maintained transport and test the actual negotiated or requested version with a client subprocess. Keep protocol responses on stdout and operational logs on stderr. [SDK v1.8.0](https://raw.githubusercontent.com/modelcontextprotocol/go-sdk/v1.8.0/README.md) [2026-07-28 stdio](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio) [2025-11-25 transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)
- OpenAI documents a connected repository and enabled Code Review as prerequisites for GitHub review. The manual trigger is `@codex review` on the PR. The documented eye reaction acknowledges the request. Verify the submitted review and reviewed head SHA before recording completion. GitHub review focuses on P0 and P1, so an independent correctness pass should also examine medium severity. The visible connector can post a comment and read submitted reviews. A search for a separately callable external reviewer found the installed GitHub connector as the applicable route. The separate Codex GitHub Action requires an API key. [GitHub Code Review](https://learn.chatgpt.com/docs/third-party/github) [Codex GitHub Action](https://learn.chatgpt.com/docs/github-action)
- Use a root `AGENTS.md` for repository-wide instructions and review rules. Use focused `SKILL.md` files with name and description metadata under `.agents/skills/` for reusable development workflows. [AGENTS.md guidance](https://learn.chatgpt.com/docs/agent-configuration/agents-md) [Build skills](https://learn.chatgpt.com/docs/build-skills)

## OpsForge read-only comparison

Inspected [DheerajShaik/opsforge at `861fa7ebd75b87eb77b31f430c611283b6e5615a`](https://github.com/DheerajShaik/opsforge/tree/861fa7ebd75b87eb77b31f430c611283b6e5615a). The inspection covered tracked files and the Git reference. This was a workflow comparison without a runtime audit.

| Observed at that commit | KubeDoctor decision |
| --- | --- |
| Ten installed commands enter their own Python modules. Shared rendering, status and bounds sit in `common`. [Entry points](https://github.com/DheerajShaik/opsforge/blob/861fa7ebd75b87eb77b31f430c611283b6e5615a/pyproject.toml#L35-L45) [Architecture](https://github.com/DheerajShaik/opsforge/blob/861fa7ebd75b87eb77b31f430c611283b6e5615a/docs/ARCHITECTURE.md#L6-L53) | Give KubeDoctor one plugin entry point with independent CLI, collection, analysis, and rendering boundaries. |
| One versioned output envelope preserves distinctions among unavailable, unobserved, empty and zero. OpsForge deliberately gives findings precedence over coverage gaps. [Contracts](https://github.com/DheerajShaik/opsforge/blob/861fa7ebd75b87eb77b31f430c611283b6e5615a/docs/CONTRACTS.md#L31-L71) | Apply the charter's own exit policy. Required coverage gaps take precedence while the partial report carries available findings. |
| Per-utility regressions include controlled loopback TLS tests. A bounded local script and pinned-action CI run component and release packaging checks. The release workflow installs wheel and sdist into clean environments and exercises the shipped commands. [TLS tests](https://github.com/DheerajShaik/opsforge/blob/861fa7ebd75b87eb77b31f430c611283b6e5615a/opsforge/certwatch/tests/test_real.py) [Local check script](https://github.com/DheerajShaik/opsforge/blob/861fa7ebd75b87eb77b31f430c611283b6e5615a/scripts/check.sh) [Release workflow](https://github.com/DheerajShaik/opsforge/blob/861fa7ebd75b87eb77b31f430c611283b6e5615a/.github/workflows/release-regression.yml) | Combine controlled HTTP API tests with disposable-cluster coverage and a clean PATH installation, and validate CI against the revision actually tested. |
