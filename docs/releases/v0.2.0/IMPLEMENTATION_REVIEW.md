# Independent implementation review

The reviewer inspected the bundle parser and normalized evidence boundary, comparison classification, historical policy, expanded diagnostics, MCP scope and the release lab. Follow-up changes addressed the observations below. External Codex review is a separate release gate.

| Area | Material observation | Disposition and evidence |
| --- | --- | --- |
| A · Evidence identity | Several resource inventory decoders could accept two records for the same logical resource, leaving replay and owner lookup dependent on ambiguous ordering. | Tightened uniqueness across single-instance inventories. Repeated warning Events retain their record semantics. Exercise the malformed inventory and fuzz fixtures. |
| A/E · Historical owner binding | A bundle's captured Pod and container were validated, but the claimed metric workload also needed a captured UID-linked owner relationship. | Validate historical workload association against captured identity and owner evidence. Keep digest integrity distinct from producer authentication. |
| C · Timing | Comparison required evaluation at or after capture finish. Opt-in historical collection can continue after Kubernetes evaluation without changing its fixed evaluation time. | Admit valid fixed evaluation inside the capture interval. Continue to require ordered, nonoverlapping observations. The clock test includes historical capture finishing later. |
| C · Stale observations | Stale source evidence could be omitted from the aggregate rank and then masked by another successful resource observation. | Keep explicit stale coverage when ranking source evidence. The regression exercises a mixed complete and stale source. |
| C · Changed Service applicability | A Service can retain its UID while switching to ExternalName or otherwise losing the applicability of the original backend or port observation. A scope-wide checked status alone cannot certify recovery. | Compare the per-Service mode and relevant observed backend and port shape. ## Verification evidence

In the implementation workspace based on `bca2c25`, a separately compiled CLI captured synthetic Kubernetes API responses before and after the same Pod and Deployment became ready. It grouped configuration, Pod and rollout evidence under the Deployment, exported HTML and classified configuration, rollout and Service findings as resolved. A real Go MCP SDK subprocess reproduced both investigation JSON objects and the comparison with exact canonical equality.

The same before capture replayed inside Docker's network-none mode with a malformed kubeconfig and a syntactically valid challenge kubeconfig pointing to an unavailable API. Canonical CLI JSON matched both times. The control proved that the container could read the copied artifact and write the isolated marker, and the credential helper marker remained absent.

Structural manifest validation passed all 45 Kubernetes and RBAC resources under both 1.35.8 and 1.36.4 schemas. A bounded local parser fuzz exercise ran for 20 seconds with two workers, 3,678 executions, and no failures. The local kind probe failed before creating a node because the rootless Docker runtime lacks cgroup delegation. The connected local evidence above comes from synthetic Kubernetes HTTP and actual network isolation. Hosted jobs provide live-cluster validation and its revision-specific records.
